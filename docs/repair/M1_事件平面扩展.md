## 交付内容

### 1. 退避重试（schema v23）

加 `event_outbox.next_attempt_at` 列。

**为什么用列而不是 sleep**：sleep 会让整批事件一起等；
`next_attempt_at` 只让失败的那条等，其余继续投递。

```python
delay = BACKOFF_BASE_S * (2 ** (attempts - 1))   # 2, 4, 8, 16, 32 秒
```

`pending()` 只取 `next_attempt_at IS NULL OR next_attempt_at <= now`。

### 2. 事件目录（新表 `event_catalog`）

17 个事件类型登记，按 `<域>.<动作>` 命名。

**目录是可发现性，不是闸门**：未登记的类型仍可 emit——
不能因为目录没更新就丢事件。`is_catalogued()` 供查询。

### 3. DLQ 可见性

```
GET /api/agent-platform/events/dlq?project_id=&event_type=&limit=
```

以前失败事件只是 `status='failed'`，**没有任何查询入口，等于掉进黑洞**。
现在可查列表 + 按类型分组统计。

### 4. 数据新鲜度

```
GET /api/agent-platform/overview  →  .freshness
```

三态：

| 状态 | 判据 |
|---|---|
| `FRESH` | 最近事件 ≤ 5 分钟 |
| `STALE` | 5 分钟 < 最近事件 ≤ 1 小时 |
| `UNKNOWN` | > 1 小时 或 无事件 |

**无数据时 `age_seconds` 为 `null`，不编造 0。**
