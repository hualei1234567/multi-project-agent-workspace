## 1. 逐项实现细节

### S-5 · 治理层 fail-closed

**根因**（`agents_dashboard.py` `_governance_gate`）：

```python
except Exception:  # 旧代码
    self.principal = None
return True          # ← 直接放行
```

**修复**：拆分为三类失败，全部拒绝

| 场景 | 返回码 | 错误码 |
|---|---|---|
| 连不上数据库 | 503 | `governance_unavailable` |
| 主体/KillSwitch 查询异常 | 503 | `governance_unavailable` |
| 解析不到主体 | 401 | `unauthenticated` |
| 主体停用/过期 | 403 | `unknown_principal` |
| Kill Switch 触发 | 503 | `kill_switch`（保留原有） |

**设计一致性**：修复后 `_governance_gate` 与 `_policy_guard` 都是 fail-closed，消除了同一服务里两套相反策略的问题。

**保留**：`PUBLIC_PATHS`（`/healthz`、`/api/auth/token`）不走闸门，治理故障时仍可探活。

### S-1 · 三个入口项目级隔离

**根因**：`_project_from_query` 只查项目是否存在，不查权限。

```python
# 旧
def _project_from_query(self, query, default=None):
    project_id = (query.get("project") or [default])[0]
    return platform_service.state_meta(project_id)   # 零权限
```

**修复**：

```python
def _project_from_query(self, query, default=None, action="read"):
    project_id = (query.get("project") or [default])[0]
    if not project_id:
        raise PlatformError("project_not_found", 404)
    project = platform_service.state_meta(project_id)
    if not self._gate_project(str(project.get("id") or project_id), action):
        raise PlatformError_AccessDenied()   # 响应已由闸门写出
    return project
```

**三入口**：

| 入口 | 修改 |
|---|---|
| `/api/state` | 入口处直接 `if not self._gate_project(project_id, "read"): return` |
| `/view` | 经 `_project_from_query`，捕获 `PlatformError_AccessDenied` 后停止 |
| `/api/file` | 同上 |

**错误信息原则**：不区分「项目不存在」与「无权限」，避免被用来探测其他项目是否存在。

**注意**：`safe_project_path` 防的是**路径穿越**，不是**跨项目越权**——两者是不同维度，审计里我特意指出了这一点。

### S-2 · 审批身份改可信 Principal

**根因**：5 处审批路由全部 `body.get("approved_by")` / `body.get("requested_by")`；而 `p4/release.py:204` 的职责分离只是两个字符串比较 → 同一人填两个名字即可绕过。

**修复**：新增统一取值方法

```python
def _actor_id(self, *, required=True) -> str:
    principal = getattr(self, "principal", None)
    pid = str((principal or {}).get("id") or "").strip()
    if pid:
        return pid
    if required:
        raise PlatformError_AccessDenied()
    return ""
```

5 处调用点全部改为：

```python
actor = self._actor_id()           # 审批动作 required=True
if not actor:
    return True
```

**验证**：`grep -c 'body.get("approved_by")' → 0`

### S-6 · execution_enabled 高风险（简化方案）

**根因**：`PATCHABLE_SETTINGS` 含 `execution_enabled`，PATCH 只需 `_gate_project(id, "update")` → 普通写权限就能打开执行器。

**简化方案实现**（用户批准，不引入完整审批流）：

| 操作 | 要求 | 审计 |
|---|---|---|
| 关闭（true→false） | 项目写权限即可（紧急安全动作） | ✅ 记录 |
| 开启（false→true） | `exec_runtime:toggle` 专用权限（仅 owner） | ✅ 记录 |

**权限矩阵**：

```python
"owner":    {"*": frozenset({"*"})},                      # 可 toggle
"operator": {"exec_runtime": frozenset({"read","list"})}, # 不可 toggle
```

**审计记录内容**：`settings.execution_enabled.enable/disable`，含 before/after/actor/reason。

**版本判断**：值没变（true→true）不算高风险变更，不拦截。

**已修复**：

```gitignore

data/token
data/token.bak-*
```

**验证**：`git check-ignore -v data/token` → `.gitignore:27:data/token`

**历史检查**：该 token 是本次 R1 期间才生成的（`ls` 显示 23:16），此前仓库里的 `data/` 只有被忽略的 `platform.db`，**历史提交中无 token 泄露**。已用 `git log --all --oneline -- data/token` 确认为空。
