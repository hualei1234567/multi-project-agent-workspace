## 三、八大域逐项实现

### M1 Evaluation — 输出必须来自真实执行

**审计事实**：`run_evaluation()` 只接收调用方传入的 `candidate_outputs`，
从未接入 Runtime。评估「通过」只能证明调用方塞的字符串能过检查器。

**修复**：
- 新增 `runtime_execution_id` 参数：从 `executions` 读真实产出；
- 执行必须 `status='succeeded'`，否则 409；
- 拿不到 outputs 证据就报错，**不回落到调用方传入值**；
- 每次评估记录 `output_source`（`runtime` / `caller_supplied`）与 `output_digest`。

`caller_supplied` 路径保留（骨架期兼容），但会被显式标出来——报表能看出
「这次评估并没有真的跑过 runtime」。

### M2 Knowledge — 跨项目授权

**修复**：
- 新表 `knowledge_grants`：接收方、用途、有效期、审批人、撤销原因；
- 检索 SQL 直接 JOIN 授权表并校验 `approved` + 未撤销 + 未过期，
  **不存在「先全局召回再过滤」的窗口**；
- 每条命中带 `grant_id` 与 `via_grant`，读者知道这条为什么能看到；
- 撤销立即生效（同一事务内更新节点状态）。

验收用例覆盖：未授权为空 / 授权后可见 / 撤销后立即不可见 / 过期无效。

### M3 Workflow — Human Gate 真阻断

**审计事实**：`human_gate` 原来只是 `human_gates: [...]` 的一个统计值，
写进 test 结果就完了，**流程照走**。

**修复**（新表 `workflow_runs` / `workflow_node_runs` / `workflow_approvals`）：

状态机：`running → waiting_approval → completed`

关键设计：
1. **闸门到达即停**：运行整体置 `waiting_approval`，下游节点保持 `pending`；
2. **审批绑定输入摘要**：`input_digest` 一变，旧审批自动失效；
3. **审批人必须可信**：空审批人直接拒绝，不接受匿名；
4. **撤销即重新阻断**；
5. **非闸门节点的完成由第三期 task 状态回推**——本域不执行任务，
   凭空假设它们完成会让闸门形同虚设（这是实现中发现的真实设计要点）。

### M4 Release — 真实流量与仿真必须分开

**审计事实**：`publish()` 只改 status，没有任何东西阻止一个没接流量的发布
被当成「已上线」。

**修复**：
- `agent_releases` 增加 `release_mode`（`SIMULATED` / `LIVE`）+ `traffic_entry`；
- 默认 `SIMULATED`；
- 声明 `LIVE` 必须提供流量入口证据，否则 422；
- 声明 `SIMULATED` 却带 `traffic_entry` 也拒绝（调用方自己没搞清楚时拒绝而不是替它猜）；
- **SIMULATED 发布不能开真实 Canary**（409 `simulated_release`），
  只能用 `simulate_canary` 做演练，记录明确标 `simulated` / 0% 流量。

### M5 Improvement — 可比的改进

新增 `baseline_eval_run_id`：基线与候选必须使用**同一数据集版本和评估器版本**，
否则 422 `incomparable`。`delta` 在缺分数时返回 `None` 而非 0。

### M6 Outcome — 成本口径（承接 R2）

`cost_summary()` 改为读三档口径，未知金额返回 `None` 并给覆盖率。
实测 material：估算 $1.728，覆盖率 87.58%，183 条未知显式披露。

### M7 Autonomy — 自动降级

**审计事实**：`required_automation` 只有测试调用，生产无调用方；没有自动降级。

**修复**：
- `evaluate_downgrade()`：连续失败 ≥3 / 质量回退 / 预算耗尽 / 运行时不可用 /
  kill switch 触发 → 降一级；
- **只降不升**（代码里没有任何提升分支），恢复等级必须重新举证 + 人工审批；
- 降级动作写 `autonomy_changes` + 事件 + 审计。

### M8 Catalog — ref 必须可解析

**审计事实**：`ref_id` 是自由字符串，上架一个不存在的资源也能成功。

**修复**：
- `resolve_ref()` 按能力类型查真实表：agent→`project_agents`、
  workflow→`workflow_versions`、domain_pack→`knowledge_items`；
- 解析失败 → 422 `dangling_ref`，不允许上架；
- skill 定义在文件系统里、平台库无法验证，如实标「未解析」并说明原因
  （soft，不拒绝，但记录 `ref_resolved=0`）。

## 四、实现中发现并修复的真实缺陷

这两个是在**真实执行**中暴露的，不是测试能发现的：

### 4.1 重试成功后任务永久卡在 blocked

第一次失败 → `todo → blocked`；重试成功要 `blocked → review`，
但状态机只允许 `blocked → in_progress`，同步代码没补中间态。

后果：**执行成功了，任务却永远显示「阻塞」**——比不更新更误导。

修复：`_sync_task_status` 在 `blocked` 时先回 `in_progress` 再进 `review`。

### 4.2 重跑的执行记录永远是第一次的结果

`_record_execution` 用 `INSERT OR IGNORE`，同一调度项重跑时旧记录挡住新结果。

后果：**第一次失败、第二次成功，库里永远显示失败**。

修复：改为按 id upsert，让执行记录反映最近一次真实结果，
并保留已有的 `actual_cost_usd`（`COALESCE`）。

两条都已加回归测试锁定。

## 七、遗留与风险

1. **真实 Canary 未验证**：平台没有流量路由能力，Release 只能标 SIMULATED。
   按规格，要标 VERIFIED 必须先有真实流量入口并完成演练——本次不做。
2. **只跑了一条链路**：material 的受控试点。ddp 未接入，符合「试点失败不影响其他项目」。
3. **`dispatch_logs` 未按 attempt 隔离**：同一调度项重跑时两段日志共用一个 item_id，
   排查时需要人工分辨。属于可用性缺陷，不影响数据正确性，留待后续。
4. **Knowledge FTS 中文分词**：FTS5 默认 unicode61 不切中文，整段中文是一个 token。
   现有测试用英文标识词规避。中文检索需要换分词器，属独立议题。
5. **验收状态**：按规格「用户验收后才标记 ACCEPTED」。当前是 **DELIVERED / 待验收**。
