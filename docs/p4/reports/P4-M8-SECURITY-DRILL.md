# 跨项目越权渗透演练报告

> 日期：2026-11-06
> 依据：V6.0 §32.1（安全零指标）、P4-M8「至少两个隔离测试项目完成跨项目越权测试」
> 脚本：`scripts/p4_security_drill.py`　证据：`docs/p4/reports/security-drill.json`
> 结论：**11/11 通过**（修复后）；修复前为 7/11

---

## 1. 方法（以及为什么这么做）

演练用两个隔离测试项目 `sec-a` / `sec-b`，**不用真实业务项目**，跑完即弃的临时库。

macOS 防火墙会静默丢弃外部入站连接，从局域网 IP 连本机服务会直接断连。
因此没有假装"从外网打进来"，而是起两个真实 HTTP 服务：

| 服务 | 来源地址 | 用途 |
|---|---|---|
| 回环服务 | 127.0.0.1 | 验证"本机免令牌"未被破坏 |
| 远端服务 | **203.0.113.7**（TEST-NET-3） | 在 `setup()` 里改写 `client_address`，其余走真实链路 |

**唯一差别是 TCP 来源地址**，令牌解析、主体映射、Policy 判定、路由全部是线上代码。

## 3. 演练发现的真实缺陷（已修）

**首轮 11 项中 4 项 FAIL**，全部指向同一个根因：

> 项目级授权只加在了**执行类**路由上（调度执行、运行时动作），
> 普通读写路由（任务列表、任务创建、知识检索）没有任何项目级校验。

后果：**任何持合法令牌的远端可以读写全部项目**——这正是 V6.0 §32.1
「未授权跨项目读取/写入 = 0」要求阻断的那件事。

修复：在 HTTP 层加入**项目级粗粒度闸门** `_gate_project()`，
在 `do_GET` / `do_PATCH` / `do_PUT` / `do_DELETE` 和 `_project_post` 的入口处统一判定：

- GET → 需要 `read`
- 其它动词 → 需要 `update`
- 平台所有者（本机）直接放行，远端必须是对应项目成员

细粒度权限（谁能发布、谁能审批）仍在各路由用 `_policy_policy` 二次判定。

## 4. 仍未覆盖的部分（不要当成"已证明安全"）

| 项 | 状态 |
|---|---|
| 真实网络来源（跨机） | 未验证，本机防火墙不允许入站 |
| 令牌暴力枚举 / 时序攻击 | 未测试 |
| Agent 主体越权（运行中 Agent 自我提权） | 仅有单元测试 |
| Secret 泄漏到日志 | 仅覆盖入库路径，日志路径未扫描 |
| 权限变更后的会话失效 | 未实现会话概念，故不适用 |
| 备份恢复后的越权 | 见 `P4-M8-BACKUP-DRILL.md`，部分覆盖 |

**结论**：本次演练证明"未授权的跨项目读写会被服务端拒绝"，
不证明"系统整体安全"。上一张表列的都是未验证项。
