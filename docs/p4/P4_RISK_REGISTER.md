## 2. 本期实测新增风险（R19–R25）

### P4-R19 无主体身份，全部零安全指标不可证（**P0 阻断**）

- **证据**：`auth.py:99-131` 只有 loopback 判断 + 单令牌等值比较；全库无 principals/roles。
- **影响**：V6.0 §32.1 的 S-01/S-02/S-07 三条零指标**无法证明**。任何"我们很安全"的表述都没有证据支撑。
- **概率**：100%（已存在）；**影响**：严重（安全门禁不可过）
- **Owner**：Security Owner（待指定）
- **缓解**：P4-M1 首批实现 `principals` + `project_members` + `authorize()` 中间件 + 两项目越权测试。
- **剩余风险**：中（实现后仍需测试证明）
- **关闭证据**：两个隔离测试项目越权用例全部 403，命中数 0。
- **状态**：OPEN

### P4-R20 无 Kill Switch，无法即时止损（**P0 阻断**）

- **证据**：停止执行只能改 `AGWS_PLATFORM_EXECUTOR` 并重启进程；重启会中断进行中的任务。
- **影响**：P4-SEC-006、S-06 不可满足；故障时响应时间是"重启进程"，不是秒级。
- **概率**：100%；**影响**：高
- **缓解**：`kill_switches` 表 + 每个执行入口前置检查 + 5 秒内生效 + 审计。
- **关闭证据**：触发后新请求全部被拒，进行中任务按策略终止，有审计记录。
- **状态**：OPEN

### P4-R21 无 git remote，无 CI 与 MR 流程（**P0 阻断**）

- **证据**：`git remote -v` → 空；V6.0 §0.1 声明代码托管公司 GitLab。
- **影响**：§27 CI/CD、§28.4 Worktree 并行、P4-REL 的发布门禁都缺少基础设施；质量只能靠本地测试。
- **概率**：100%；**影响**：高（流程性）
- **缓解**：P4-M1 DoR 记录为已知限制；请用户提供 GitLab 地址后补齐。**在此之前不得声称有 CI 门禁。**
- **关闭证据**：`git remote -v` 有值 + 一次 CI 通过记录。
- **状态**：OPEN（需用户输入）

### P4-R22 运行时状态陈旧，可能展示虚假实时（**P0 阻断**）

- **证据**：`runtime_checks` 最新记录 `2026-11-05T11:41`，落后一天；采集线程已停。
- **影响**：违反 V6.0 §32.2「不展示虚假实时状态」；平台 UI 显示的服务健康度不可信。
- **概率**：100%；**影响**：中高
- **缓解**：重启采集线程 + 心跳告警 + UI 显示数据新鲜度。
- **关闭证据**：`runtime_checks` 时间戳 < 2×采集周期，UI 显示"更新于 X 分钟前"。
- **状态**：OPEN

### P4-R23 执行与任务数据链断裂（**P0 阻断**）

- **证据**：`executions.task_id` 44 条全为 NULL；调度执行未写 `executions(source='dispatcher')`；`token_usage_events` 无 cost 列。
- **影响**：P4-OUT-003（任务级成本归因）、R-01（重试次数）、H-03（人工接管）全部 BLOCKED；评估运行无法与执行事实对齐。
- **概率**：100%；**影响**：高
- **缓解**：P4-M1 先补 `task_id` 写入与 dispatcher 执行记录；P4-M6 前 Expand 加 cost 列。
- **关闭证据**：新产生的执行 100% 有 `task_id` 与 `source`；成本可追溯到 `price_version`。
- **状态**：OPEN

### P4-R24 执行器策略自相矛盾（高）

- **证据**：`executor_policy.py:132` `--disallowedTools Bash`，而 `ALLOWED_BASH_PREFIXES` 定义了 30+ 白名单前缀，永远用不上。
- **影响**：执行器无法运行 pytest/ruff，与 `docs/三期建设方案.md` T3-103 描述不符；白名单成死代码，给人"已限制"的错觉。
- **缓解**：要么移除白名单（承认无 Bash），要么改为按前缀放行；必须先出 ADR 再改。
- **状态**：OPEN

### P4-R25 无 Secret 扫描，日志含代码与路径（高）

- **证据**：`dispatch_logs` 存 `claude` 原始输出（178 行）；无任何脱敏或 Secret 检测代码。
- **影响**：P4-SEC-003、S-03 无法满足；知识索引上线后 Secret 可能入库。
- **缓解**：M1 在日志落盘与知识导入两处加扫描；命中阻断而非打码。
- **状态**：OPEN

## 3. 风险处理优先级（P4-M1 首批）

| 顺序 | 风险 | 理由 |
|---|---|---|
| 1 | R19 身份与授权 | 所有零安全指标的前提 |
| 2 | R20 Kill Switch | 出事时的唯一止损手段 |
| 3 | R23 数据链断裂 | 影响评估与 ROI 两个域 |
| 4 | R22 运行时陈旧 | 低成本、直接违反规范 |
| 5 | R14 事件平面缺失 | 横跨所有域 |
| 6 | R21 GitLab/CI | 需用户输入，可并行等待 |
| 7 | R25 Secret 扫描 | M2 前的硬前置 |
| 8 | R24 执行器矛盾 | 小修，但需 ADR |
