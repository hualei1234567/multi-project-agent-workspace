# 项目纳管约定

平台纳管项目的唯一清单是 `config/projects.json`。但「任务、角色状态、报告」的事实来源有两种模式，
由项目自身是否具备 `ai-team/` 目录决定 —— 平台不会替项目编造数据。

## 模式 A：仓库内 `ai-team/`（DDP 现行）

事实来源在项目仓库里，平台只做只读汇总：

| 采集项 | 来源 |
|---|---|
| 任务 | `ai-team/TASK_BOARD.md`（`TEAM-xxx`） |
| 角色自报 | `ai-team/status/*.json` |
| 交付/报告 | `ai-team/reports/`、`docs/reports/` |
| 代码分支/工作区 | 项目仓库 + `~/agent-team/<id>-team/worktrees/` |

适用：有多角色协作、需要把任务板随代码一起版本化的项目。DDP 用这一种。

## 模式 B：平台库（Material 现行）

项目没有 `ai-team/` 时，`/api/state` 的任务/看板回落到平台库
（`tasks` / `project_agents` / `deliveries` 表），与仓库文件互不干扰。
MaterialDev 目前是这一种：7 个角色已建（全部 offline），任务 0 条。

> 没有 `ai-team/` 不是缺陷，只是还没接入仓库侧协作流程。**不要为了填满看板在 MaterialDev
> 仓库里造 `ai-team/` 文件**；MaterialDev 有自己的 `AGENTS.md` / `docs/governance` 体系，
> 是否引入 ai-team 由项目负责人决定。

### 在模式 B 下维护任务

```bash
# 建任务（task_key 省略时自动生成 T-XXXXXX）
curl -s -X POST http://127.0.0.1:8099/api/projects/material/tasks \
  -H 'Content-Type: application/json' \
  -d '{"title":"盘点多仓库存差异","priority":"P1","task_key":"MAT-001"}'

# 改状态（乐观锁，需带 expected_version）
curl -s -X POST http://127.0.0.1:8099/api/projects/material/tasks/<task_id>/transition \
  -H 'Content-Type: application/json' \
  -d '{"to_status":"in_progress","expected_version":1}'

# 关依赖（DAG）
curl -s -X POST http://127.0.0.1:8099/api/projects/material/tasks/<task_id>/dependencies \
  -H 'Content-Type: application/json' -d '{"depends_on":"<other_task_id>"}'
```

注意：**没有删除任务的 HTTP 接口**。建任务前确认标题与 key；需要清理时在库上按显式 ID 操作，
并遵守「删除类操作先 dry-run、逐条确认、带计数、先备份」的硬规则。

### 模式 B 下角色状态

`project_agents.status` 取值为 `working / idle / blocked / offline`，平台按角色 key 展示。
目前没有对外写接口，状态更新走平台库；一旦项目采纳 `ai-team/status/*.json`，会自动切换成模式 A
（文件优先，库只补缺）。

## 从 B 升级到 A

1. 项目仓库建 `ai-team/TASK_BOARD.md`、`ai-team/status/<role>.json`、`ai-team/reports/`。
2. 把平台库里的在途任务按 key 对齐到任务板（避免同一任务两处各有一份）。
3. 重启平台：`build_state_for_project` 检测到任务板后优先读仓库，库只用于补缺。

## 新增一个项目

1. 代码放 `~/vscodeworkspace/<repo>/`，团队目录 `~/agent-team/<code>-team/`。
2. `config/projects.json` 加一条：`id/code/name/repo_root/team_dir/default_branch/session_slugs`。
   `session_slugs` 必须列全该项目在 `~/.claude/projects/` 下的**所有**目录名（含迁移前旧目录），
   平台按**精确名单**过滤，不再做前缀匹配 —— 否则同名前缀的仓库会串台。
3. 重启平台，`service.bootstrap` 自动登记并建 7 角色。
