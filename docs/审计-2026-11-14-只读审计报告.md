### 需要纠正审计初稿的一处

两份初稿都写「监听 0.0.0.0 + 鉴权默认关闭」。**实测不成立**：

```
lsof -iTCP:8099 → 127.0.0.1:8099 (LISTEN)
curl http://<LAN_HOST>:8099/healthz → 000（拒绝）
app/agents_dashboard.py:2775  parser.add_argument("--host", default="127.0.0.1")
```

鉴权默认 `off` 属实（`auth.py:122`），但**只监听回环，局域网进不来**。风险等级应从「局域网裸奔」下调为「若将来开 `--tailscale` 或改 host 则立即裸奔」。这条差异必须如实记录，不能照抄初稿。

## 8. 决策建议

### 8.1 关于 P3-M8（必须先定）

三条路，各有代价：

| 方案 | 做法 | 代价 | 我的建议 |
|---|---|---|---|
| A. 补齐三期 | 按 V4.0 补 P3-M0 五份文档 + M1/M2/M7 实现 + M8 全部演练 | 数周，且要重做已能用的东西 | 不推荐（违反 Reuse First） |
| B. 正式豁免归档 | 出一份《P3-M8 风险接受记录》：谁接受、接受什么、有效期、缓解措施 | 半天，但必须真实签署 | **推荐**：把已存在的口头裁定固化成文档 |
| C. 里程碑换轨 | 确立「M3-0～M3-4 = 事实基线，V4.0 P3-Mx = 目标架构」的映射，重新定义验收口径 | 需要你认可新的口径 | **推荐，与 B 并行** |

### 8.2 关于四期（我的判断）

**不要回退四期代码**。8 个域的骨架是可复用的资产，回退等于扔掉 2914 行和 72 项测试。

正确做法是：**以「P4-M0 返工」名义进入**，先清 4 个 P0 安全阻断项，再补证据。

### 8.3 建议的执行顺序（DAG）

