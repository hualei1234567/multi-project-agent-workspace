# CF-6 · Full Auto（M9）契约（冻结）

> 冻结日期：2026-11-15
> 依据：用户决定「要建设 Full Auto」+ 蓝图 §3「Full Auto 仍需独立立项和授权」
> **本契约是独立立项的依据**，不与 ASSISTED 混在一起

---

## 1. 与 ASSISTED 的本质区别

| 维度 | ASSISTED（现状） | FULL_AUTO |
|---|---|---|
| 触发 | 人点「执行」 | 平台自动挑选 |
| 审批 | 每个动作都要 | 按策略（可选免审） |
| 失败处理 | 人介入 | 自动重试 → 熔断 |
| 无人值守 | 否 | **是** |
| 风险 | 可控 | **能自己改代码并继续改** |

---

## 2. 五个硬前置（缺一不可）

| # | 前置 | 状态 |
|---|---|---|
| P1 | 三模式（SHADOW/RECOMMEND/ASSISTED） | ✅ M3 |
| P2 | 预算控制（超支暂停新任务） | ✅ M7 |
| P3 | 熔断（连续失败自动暂停） | ✅ 本次 |
| P4 | 可观测（告警 + 状态可见） | ⏳ 部分 |
| P5 | 不 push / 不部署 / 不删数据 | ✅ 始终如此 |

**任一缺失都不允许开启 FULL_AUTO。**

---

## 3. 自动派发循环

```
每 N 秒（默认 60）：
  1. 全局开关 FINAL_AUTO_ENABLED？ 否 → 退出
  2. 遍历项目：
     a. 熔断中？ → 跳过
     b. 预算超限？ → 跳过
     c. 生成 recommend 候选
     d. 对每个候选：Policy 判定 → 通过则创建 assisted 计划并执行
  3. 每轮最多派发 max_per_round（默认 1）项
```

**为什么每轮最多 1 项**：无人值守时并发改同一仓库会互相踩。
宁可慢，不可乱。

---

## 4. 审批策略（关键决策）

Full Auto 下"每个动作都要审批"意味着人必须守着，那就不是自动了。
但完全不审批等于把闸门拆了。

**分层策略**：

| 风险 | 审批 |
|---|---|
| R0–R1（只读/低危） | 免审 |
| R2（常规改代码） | 免审（Full Auto 前提） |
| **R3+（派发执行到生产/高风险）** | **仍需审批** |
| push / 部署 / 删数据 | **永远禁止** |

**实现**：`policy_rules` 里 FULL_AUTO 免审的规则 `max_risk='R2'`，
R3 以上仍命中 `requires_approval=1` 的规则。

**这是本契约最重要的决策**：Full Auto 放开的是"不点按钮"，
不是"不设边界"。

---

## 5. 停止机制（三层）

| 层 | 手段 | 响应时间 |
|---|---|---|
| 1 | 全局开关 `AGWS_PLATFORM_FULL_AUTO=off` | 重启生效 |
| 2 | 项目熔断 `/circuit/reset` 的反向 | 秒级 |
| 3 | Kill Switch | 秒级 |

**Full Auto 必须在 Kill Switch 下立刻停住。** 这是硬要求。

---

## 6. 不做什么

- **不做**跨项目自动组队
- **不做**自动 commit/push（永远禁止）
- **不做**自动部署
- **不做**自动删除数据
- **不做**没有预算的自动派发

---

## 7. 开启流程（独立授权）

```
1. 确认 P1–P5 全部就绪（脚本检查）
2. 设置预算（至少一条 project 级）
3. 显式设置 AGWS_PLATFORM_FULL_AUTO=on
4. 观察第一个 24 小时，记录每轮派发
5. 无异常后才可放宽 max_per_round
```

**未完成步骤 1–3 时，Full Auto 循环必须拒绝启动**（fail-closed）。
