### Q2 · 建设 Full Auto

**这是重大范围扩大，必须说清楚风险：**

V4.0 蓝图 §3 明确写「Full Auto 仍需独立立项和授权」。
用户现在给了授权，但 Full Auto 意味着：

| 维度 | ASSISTED（当前） | Full Auto |
|---|---|---|
| 派发触发 | 人点按钮 + 审批 | 平台自动 |
| 审批 | 每个动作都要 | 按策略批量/免除 |
| 失败处理 | 人工介入 | 自动重试/熔断/升级 |
| 风险 | 可控 | **无人守着也能改代码** |

**新增里程碑 P3-M9（Full Auto）**，前置条件：
1. P3-M3 三模式完整（SHADOW/RECOMMEND/ASSISTED 全跑通并稳定）
2. 预算控制（P3-M7）— 无人值守时超支无人拦
3. Git 侧保护：执行器不自动 commit/push（现状如此，需保持）
4. 熔断 + 告警 + 可观测性
5. **独立验收**，不与 ASSISTED 混在一起

**不改变的红线**：
- 执行器仍不 push / 不部署 / 不删数据
- 高风险动作仍需审批
- Kill Switch 始终可秒级停止

### Q4 · PWA 推送通知

**前置依赖问题（必须说清楚）**：

Service Worker 只在**安全上下文**注册：
- `https://` ✅
- `http://localhost` / `127.0.0.1` ✅
- `http://<局域网 IP>:8099` ❌ **不能注册 SW**

当前平台是 HTTP + 局域网 IP，所以：
- 本机浏览器测试可用（localhost 是安全上下文）
- 手机上通过 `http://192.168.x.x:8099` 访问**装不了 PWA，也收不到推送**

**三条可行路径**：

| 方案 | 成本 | 说明 |
|---|---|---|
| A. Tailscale + HTTPS | 低 | tailnet 内可用 `https://<host>.ts.net`，Tailscale 自动签发证书 |
| B. 自签证书 + 本机 CA | 中 | 手机要装 CA 证书，体验差 |
| C. 内网穿透 + 公网 HTTPS | 中 | 引入外部依赖，暴露面变大 |

**建议 A**。用户已有 `--tailscale` 模式（`auth.py` 提到过）。

推送还需 VAPID 密钥对 + 保存订阅到数据库。**密钥不能进仓库**。

### Q5 · 跨项目委派暂不需要

**改动**：
- P3-M5 缩减：只做 Global Task（统一任务视图），
  不做委派状态机、Context Package、目标 Owner 接受/拒绝
- 相关表（`delegations` / `context_packages`）**不建**

**理由**：只有 material + ddp 两个项目，且 material 是主战场，
跨项目委派没有真实场景。为了架构完整性建一套没人用的流程是浪费。
