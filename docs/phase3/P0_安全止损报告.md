## 修了什么

审计发现的唯一真实安全缺陷：**审批闸门形同虚设**。
不是代码没写，是 `policy_rules` 表生产库为空 → `requires_approval` 恒为 False
→ 点一下调度项就能起真实 `claude` 进程，无任何审批。

### 改动 1 · 执行器默认关闭

`scripts/start.sh`：

```diff
-# 执行器默认开启：本机即服务器，平台的托管会话/派发要用它。
-export AGWS_PLATFORM_EXECUTOR="${AGWS_PLATFORM_EXECUTOR:-on}"
+# 执行器默认关闭（与 executor_policy.py 的 Deny-by-Default 一致）。
+# 需要平台真实派发时显式传 AGWS_PLATFORM_EXECUTOR=on。
+export AGWS_PLATFORM_EXECUTOR="${AGWS_PLATFORM_EXECUTOR:-off}"
```

这行与 `executor_policy.py` 文档写的「默认 off」原本是矛盾的，现在一致了。

**验证**（KeepAlive 重启后实测）：
```
$ launchctl stop com.hualei.agent-platform && sleep 2
$ ps eww -p 88288 | grep AGWS_PLATFORM_EXECUTOR
AGWS_PLATFORM_EXECUTOR=off
$ curl /api/projects/material/dispatch/executor | jq .global_enabled
false
```

### 改动 2 · 新增通用审批服务

`app/agent_platform/approvals.py`（新文件）：

- `request()` — 发起审批，同对象同动作复用 pending，不堆积
- `decide()` — 批准/驳回，检查过期
- `consume()` — 执行前消费，**摘要绑定** + **一次性**
- `list_pending()` — 待审批列表

关键设计：
- **摘要绑定**：`digest = sha256(project_id, resource_type, resource_id, action)`。
  批准 A 不能拿去执行 B。
- **一次性**：消费后 `status='consumed'`，不能复用。
- **不覆盖人工备注**：初版想用 `decision_note` 前缀标记，会吃掉审批意见，
  改为直接改 `status`。

### 改动 3 · 三个审批 API

| Method | Path | 说明 |
|---|---|---|
| GET | `/api/projects/{id}/approvals` | 待审批列表 |
| POST | `/api/projects/{id}/approvals` | 发起申请 |
| POST | `/api/projects/{id}/approvals/{aid}/approve` | 批准 |
| POST | `/api/projects/{id}/approvals/{aid}/reject` | 驳回 |

### 改动 4 · run 端点接入审批闸门

```python
if not dry:
    if not self._policy_guard(project_id, "dispatch_item", "run", risk="R3"):
        return
    # 审批闸门：Policy 说「需要审批」时，必须消费一张已批准的审批单。
    if not self._consume_approval(project_id, "dispatch_item", rest[2], "run"):
        return
```

`dry-run` 不受限——它只返回 argv，不起进程。

### 改动 5 · 初始化审批规则

`scripts/seed-policy-rules.py`（新脚本，幂等）：

| 规则 | 资源/动作 | 说明 |
|---|---|---|
| `rule-dispatch-run-approval` | `dispatch_item/run` | 派发起真实进程 |
| `rule-runtime-run-approval` | `runtime_action/run` | 运行时一键操作 |
| `rule-release-publish-approval` | `agent_release/publish` | 发布到生产 |

执行前已备份：`data/platform.db.bak-policy-20261115-161434`（11M）。

```

{"ok": false, "error": "approval_required", "message": "该操作需要审批，请先发起并获批"}

$ curl -X POST .../approvals -d '{"resource_type":"dispatch_item",...}'

消费一次 → 成功；再消费 → 拒绝（一次性 ✅）
审批单状态：consumed，decision_note 保留「验证通过」✅
```

Policy 层实测：
```
dispatch_item/run risk=R3 -> allowed=True requires_approval=True matched=['rule-dispatch-run-approval']
release/read    risk=R1 -> allowed=True requires_approval=False matched=[]
```

## 对既有使用的影响

| 场景 | 影响 |
|---|---|
| 本机浏览、查看看板 | 无影响 |
| `dry-run` 预演 | 无影响（不受审批限制） |
| 真实派发执行 | **需先申请审批**（这是修复目的） |
| 运行时一键操作 | **需先申请审批** |
| 发布到生产 | 原本就要审批（release 有自己的流程），现多一层通用闸门 |

要恢复"点一下就执行"，显式设置 `AGWS_PLATFORM_EXECUTOR=on` **并且**删掉对应
`policy_rules` 行。**不建议**——那正是审计要消除的状态。
